fix(ocr): 恢复 size 阈值 + 补齐 workbook 黑名单模式

上一版 00edc07 的 4KB 阈值太严，把 3116 bytes 的真实小图也拦下了 —— 用户截图里
"?????C?????" 的头 80 字符是用 `replace(/[^\x20-\x7E]/g, '?')` 把二进制转成问号显示，
实际上是合法 JPEG/HEIC 二进制，不是 XML/HTML。

实际根因：
1. 3116 bytes = 真实的小图片（学生在 H5 端压缩过狠或原始图本来就小），
   AI 视觉模型看到 3KB 图必然返回 0 道题，但这属于"内容问题"应在 OCR 层处理，
   不应在 downloadImage 层硬拦。
2. workbook 0 道题抛出的 errorDetail 是 "1 页识别失败" / "3 页识别失败"，不在上一版
   黑名单里 → PendingTaskRecovery 仍然把它重新入队 → 反复 0 道题 → 反复入队。

修复：
1) server/utils/imageValidator.js
   - size 阈值回退到 1024 bytes（只挡连魔数都不完整的小 buffer）
   - 4KB+ 真实 JPEG/PNG/WebP/HEIC 一律放行，由 OCR 层用 0 道题重试机制处理
   - 仍拦 XML/HTML 头部 + 未知魔数

2) server/pendingTaskRecovery.js
   - 加 /页识别失败/ 模式（workbook "1 页识别失败" / "3 页识别失败"）
   - 加 /OCR 未识别到任何题目/ 模式（answer bank 流程的同类问题）
   - 上一版的 /所有页面识别结果为空/ 和 /AI_EMPTY/ 保留

3) server/worker.js#processWorkbookGrading 0 道题时主动 rotateVLModel 切下一个
   视觉模型（235B / 8B-Thinking）重试 1 次的逻辑保持不变。

测试：
- imageValidator：3116 bytes 真实 JPEG ok=true；XML/HTML < 1024 拦下；5KB JPEG/PNG/HEIC 全通
- 黑名单：1 页识别失败 / 3 页识别失败 / OCR 未识别到任何题目 全部 skip=true
