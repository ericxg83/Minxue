「完成复核」后仍显示待复核 / 待完成 · 根因排查与修复

敏学 P0 事故 · 2026-09-14 · 复现样本：余晨瑞 · 错题再测-0911 · commit 2a57ab3
一条 SQL 的类型推断错误，炸在结算流程的最后一步之前；前端又把这个异常 静默吞掉。于是界面提示「试卷复核完成，已保存」，库里却什么都没写 —— PC 左侧一直「待复核」、移动端一直「待完成」，两个症状是同一个根因。
受影响链路
2 条重练卷结算 + 作业批改掌握度结算
线上已结算的重练卷
0 / 25全部从未写成功
回归测试
284 / 284新增 5 例锁口径

根因链路

1
批量回写题目正误的 SQL 缺类型转换 已修 SET is_correct = CASE id WHEN $1::uuid THEN $2 … END —— THEN 分支的参数没有类型上下文，PostgreSQL 把它推断成 text，整条语句抛 42804：column "is_correct" is of type boolean but expression is of type text。
注：CASE WHEN $n THEN … 把参数放在条件位置时没这个问题（WHEN 有布尔上下文），所以同文件里其它写法一直是好的。
2
炸点夹在两段写入之间 结算顺序是：错题生命周期推进 → 批量回写题目正误（炸在这里）→ 写 exam.status='graded'。前两段是非事务的独立语句，已提交；第三段永远执行不到。
3
前端把异常吞了 已修 persistTaskCompletion 对 gradeGeneratedExam() 用了 .catch(console.error) → 后端 500 被吃掉，照常弹「试卷复核完成，已保存」并把本地卷标成已复核。假成功就此产生。
4
两端读的都是同一个未被写入的字段 PC 的 resolveRetryPaperState 判「已确认」、移动端 ExamPageV2.stage() 判「已完成」，都只看 exam.status === 'graded'。它没被写 → 两端同时卡住。
5
副作用：错题数据被反复推进 炸点之前的 SQL 每次都成功提交，所以老师每点一次「完成复核」，wrong_questions 的生命周期与 practice_count／error_count 就重复累加一次（样本卷 practice_count 已达 30、答错题 error_count 27）。

判据（只读取证，不靠猜）

观察含义
generated_exams.updated_at === created_at该卷从未被结算写过 —— 落库链路断了
judgements 里没有 generated_exam:* / task:* 的 settlement_key对应结算链路从来没跑通过（不只是这一次）。全库当时只有 rejudge:*，说明作业批改的知识点／掌握度结算也一直在失败
wrong_questions.practice_count 远大于实际练习次数失败调用反复推进前半段 SQL 留下的脏计数

定位手法：事务内 dry-run（零副作用）

在 BEGIN … ROLLBACK 里按顺序复跑结算的全部 SQL，能精确报出炸在第几步。 比读代码猜快一个数量级 —— 本次一次就拿到 42804 原文。样板保留为 server/_diag_grade_dryrun.mjs。

STEP 4: update questions  (params=34, n=17)

   hint: You will need to rewrite or cast the expression.
回滚后 exam 状态（应保持不变）: { status: 'ungraded', updated_at: '2026-09-11T02:44:40.557Z' }

修复内容

文件改动
server/services/gradingFinalizer.js 抽出唯一构造器 buildIsCorrectAssignments(ids)，THEN 分支一律显式 ::boolean； 两处结算（finalizeGradingBatch / finalizeGeneratedExamResults）共用，禁止再内联裸 CASE。 顺带修好作业批改的知识点／掌握度结算。
src/workbench/stores/reviewStore.js 核心状态写入不再静默失败：去掉 .catch(console.error)，异常上抛； 自动完成路径失败时不标记本地已复核、不跳下一份，新增 saveError 交给 UI。
src/workbench/components/review/ReviewTopBar.vue 落库失败时展示服务端真实原因，不再一律提示成功。
server/worker.js slim 全自动结算失败时不再打印「组卷已标记 graded」，避免日志掩盖故障。
test/gradingSettlementSql.test.mjs（新增） 锁定：占位符与 ::boolean 严格对位、禁止裸 CASE、exam 状态必须写在题目回写之后。
server/scripts/repair-retry-exam-settlement.mjs（新增） 补结算事故期间「点过复核但没落库」的卷。默认只列不写，须显式 --exam／--all-pending。

遗留与建议

  • 脏计数未回补：样本卷 practice_count 30→31、答错题 error_count 27→28。 属展示型统计字段，不影响掌握度判定与队列分层；如需清理建议单独做一次计数校正，不在本次范围内。
  • 排查纪律沉淀：「提交后状态字段 / 计数」这类写入不允许 .catch(console.error)； 后台 fire-and-forget 任务也必须让日志反映真实结果，不许打印成功文案掩盖失败。
  • 线上生效依赖 Render（后端）+ Cloudflare Pages（前端）自动部署完成，约数分钟。
