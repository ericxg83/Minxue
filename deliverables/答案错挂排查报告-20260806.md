## 一、现象证据（数据库实录）

| unit_key | 题号范围 |

| 标准答案 | 实际所属单元 | 被挂到的位置 |

## 二、根因（代码级）

### 主因：2026-08-05 新增的「题号连续性分组」前置层在打平时静默锚到错误单元，并短路了全部精细匹配

`server/worker.js`：

1. **逐页预匹配打平 → 死代码兜底取第一个候选**（`_groupByQuestionContinuity`，2076–2084 行）
   - 覆盖率只判断「题号是否存在于该单元」（`${qn}|`，连 sub_no 都不看）。9 个单元同题号区间 → 多个单元覆盖率同为 1.0。
   - 打平时本应「优先选下一页所属单元」：`ordered[i + 1]?.unitKey` —— 但 `ordered` 在本层循环里只 push 到第 i-1 项，**`ordered[i+1]` 永远是 undefined**，该兜底是死代码，实际永远落到 `candidates[0]`（Map 迭代序第一个单元）。

2. **组级匹配打平 → 严格大于不换手**（2135–2145 行）
   ```js
   if (cov > bestCov) { bestCov = cov; bestUnit = uk }  // 打平时保留迭代序第一个
   ```
   9 个单元 cov 全为 1.0 → 永远是第一个单元胜出；`bestCov < 0.5` 的放弃门槛拦不住（打平也是 1.0）。

3. **分组结果直接短路 `pickAnswerUnit` 的全部 7 层精细逻辑**（2158–2160 行）
   ```js
   const groupUnit = groupOverrides.get(pageNumber)
   if (groupUnit) return { pageNumber, unitKey: groupUnit, idx }  // pageTitle/lesson_code/学生答案反推全部不执行
   ```
   你加的「多层逻辑」（pageTitle 自检、lesson_code、标题归一化匹配、章节关键词、学生答案反推、答案覆盖率兜底、页码兜底）对被分组覆盖的页**一层都没有运行**。

4. **错误经分组扩散**：逐页打平使相邻页拿到同一个 candidates[0] → 被合并成一组 → 组级匹配再次打平锚到同一单元 → 整组页（本任务中大量页面）统一错挂，且只 console.log，无告警、无 is_suspicious 标记。

### 次因（即使绕过前置层也存在的同类隐患）

- `unitCoverage`（2167–2181）双向继承同样只看题号存在性，同号单元无法区分，退回「距离近者胜」，锚点错了会沿页扩散。
- 同题号相似度兜底阈值仅 0.3（3644 行），数学短答案极易跨题命中。
- `calculateAnswerSimilarity` 的「包含即 0.85」规则 + `searchByAnswerFingerprint` 打平取第一行，会进一步把已判题改写到错误答案上。
- 页码兜底用了两个坐标系：`answer_page_start/end` 是答案 PDF 页码，`pageNumber` 是学生照片张数序号（本任务该字段全为 NULL，未触发但仍是隐患）。

## 三、为什么「多层逻辑」没拦住

多层逻辑都在 `pickAnswerUnit` 内部；而 8 月 5 日加的前置分组层在**它之前**用纯题号覆盖率做了粗决策，并通过 `groupOverrides` 直接返回，把后面所有层架空了。同号多单元场景下前置层必然打平、必然锚错，精细层根本没有出场机会。

## 四、修复建议（按优先级）

1. **前置分组层不得短路精细匹配**：分组命中结果只作为 `pickAnswerUnit` 返回 null 时的兜底，或作为一层提示注入决策链，不能直接 return。
2. **打平即放弃**：组级/页级覆盖率出现多单元并列最高时，应判定「无法区分」→ 交给后续层（标题/学生答案反推），而不是取第一个。并列时取第一是本 bug 的直接执行点。
3. **修复或删除死代码** `ordered[i + 1]?.unitKey`（单趟前向循环里永远读不到下一页）。
4. **覆盖率加入区分度**：至少把 sub_no、question_type/section 纳入覆盖键；同号单元并列时用学生答案指纹（`searchUnitByStudentAnswers` 已有此能力）做决胜。
5. **可观测性**：单元打平/分组覆盖发生时写入 `result.sectionMatch` 诊断并打 `is_suspicious`，否则错挂静默无感（本次 63 题全错无任何标记）。
6. 数据回刷：任务 cdeabcde 及同期错挂任务需用 `server/scripts/fix_misjudged.mjs` 类似流程重批。
