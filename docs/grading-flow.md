# 作业批改流程

## 入口

主要入口为：

```text
POST /api/tasks/upload
```

## 普通批改流程

1. 前端上传一张或多张作业图片。
2. 图片上传到 OSS。
3. 创建 `tasks` 记录，多页图片写入 `tasks.images` JSONB。
4. 任务进入 BullMQ；Redis 不可用时存在同步处理路径。
5. Worker 下载图片并进行旋转、归一化和压缩。
6. 视觉 AI/OCR 识别题号、题干、学生答案、题型、坐标和配图。
7. `judgeAnswer` 执行判题。
8. 缺少标准答案时，优先查询 `question_cache`，否则调用 AI 生成答案。
9. 创建 `questions` 记录。
10. 错误题目同步写入 `wrong_questions`。
11. 写入 `judgements` 审计记录。
12. 后台同步题目知识点和学生掌握度。
13. 更新任务状态、统计数据和错误信息。

## 特殊批改类型

- `taskType='workbook'`：使用练习册或答案库中的预置答案。
- `taskType='wrong_retry'`：处理错题重练。
- `resourceId`：优先使用统一资源答案库。
- `generatedExamId`：关联组卷重练批改。

## 答案来源

答案库包含资源、单元、题目和答案等层级。答案定位需要结合：

```text
unit
section
question_no
sub_no
```

不能只根据题号定位答案。AI 草稿、教师审核答案和官方审核答案具有不同状态，批改选择答案时需要保留这种差异。

## 人工复核

考试复核页面支持人工改判、修改学生答案、修改标准答案和排除题目。

- 改判正确时，错题记录保留并标记为已掌握（`mastered`），同时累计练习次数；
  不再删除记录——删除等于"这题从没错过"，会抹掉学习轨迹并让它退出重练池。
- 排除题目时，错题记录无意义，直接删除。
- 改判错误且没有错题记录时，重新加入错题；题目元素不完整（缺参考答案等）时不入册。
- 保存修改只落题目与错题本，不会改动任务状态；需显式"完成复核"才会重算任务统计
  并将任务标记为 `reviewed`。
