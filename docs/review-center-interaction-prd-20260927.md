# 批改中心交互重构 PRD（第二轮 · 2026-09-27）

> 范围：`/grade/task` 复核工作台（`ReviewWorkspace` 及其三栏子组件）。
> 前置事实核查：本页面真实技术栈为 **Vue 3 + Pinia + Element Plus + CSS 变量（`--wb-*`）**，
> 不使用 Tailwind（`package.json` 有 Tailwind 但 review 组件全部 `<style scoped>`）。
> 因此约束「保持 React + Tailwind」按其本意执行为：**保持现有技术栈、不改任何 Design Token、
> 不新增组件库、保持三栏布局、不改视觉风格**。本 PRD 只动交互与信息架构，不动样式体系。

## 1. 交互问题清单

### P0 —— 阻断「看→判→过」主循环或造成错误认知

- **P0-1 「过」是手动的，主循环断裂。**
  老师判完一题后必须再按一次 →（或移动鼠标点「下一题」）。按 40 题卷计算，每卷多 40 次击键，
  连续批改场景下这是最大的时间税。判定动作与前进动作应合并为一次按键。
- **P0-2 主按钮不唯一。**
  一页三处 primary（完成复核 / 下一份 / 下一题），视线在顶栏与右栏之间往返。违反
  「一个页面只有一个主按钮」：主按钮应随场景切换（批改中=判定区；全部确认后=完成复核），
  其余降级为次要样式。
- **P0-3 归因模态框打断判定流。**
  Space 标对一题 AI 判错的题 → 阻断式弹窗。连续批改时节奏被打断，且老师为了跳过必须
  多一次点击/按键（Tab 到「跳过」或 Esc），实际效果是大家都在盲目跳过，归因数据质量差。
- **P0-4 「撤销」承诺与实现不符（诚实性问题）。**
  菜单里的「撤销上一笔」看起来是全局撤销，实际只回退内存、不写库，且换卷即丢。老师
  撤销「标错」后以为错题本没有变化，实际 `review_status='wrong'` 已落库、错题本已同步。
  这不是体验瑕疵，是会造成错误认知的功能性缺陷。

### P1 —— 效率与可发现性

- **P1-1** 同一进度两个入口（「还差 N 题」按钮 vs 左栏「待处理」页签），语义却有微差
  （确认口径 `questionConfirmationMap` 与左栏过滤口径需人工对齐），新人困惑。
- **P1-2** 快捷键覆盖不足且不可发现：无编辑(E)、保存、删除、下一份/上一份、完成复核；
  除按钮上的 kbd 角标外没有速查入口。
- **P1-3** 判定后反馈依赖 toast（1.5s 即逝）：左栏对应行状态、当前题高亮是否滚动到可视区
  依赖实现细节，需要明确为契约。
- **P1-4** 顶栏低频元素挤占高频区域：「⚠ 待补入」在欠账为 0 时仍常驻；撤销/改批改方式等
  中频动作藏在「⋯ 更多」二级菜单里。
- **P1-5** 置信阈值 slider 是「筛选」的高级参数，却常驻导航面板底部，与题队列表混在一栏。
- **P1-6** 「完成复核」disabled 时没有解释（差几题、差哪几题），老师需要自己去左栏找。

### P2 —— 打磨项

- **P2-1** 无快捷键速查浮层（`?`）。
- **P2-2** 任务级只有「下一份」，无「上一份」，回看上一份必须回到顶栏下拉。
- **P2-3** 删除本题后永久不可见（产品设计如此），但界面无任何「已删除 N 题」的留痕提示，
  复盘时无从知道删过什么。
- **P2-4** Space 处理正确（keydown preventDefault 已阻止按钮空格激活），但鼠标点击判定按钮
  后焦点停留在按钮上，之后按 Enter 会重复判定——应在判定后主动 blur 或把焦点移到卡片容器。

## 2. 新信息架构

### 2.1 分层原则

```
卷级操作（换学生/换卷/收尾/异常入口）  → 只在 ReviewTopBar
卷级进度（还差几题/闸门欠账）          → 只在上下文条（单向只读 + 一个跳转动作）
题级导航（队列/过滤/翻题）             → 只在左栏
题级证据（原卷图/对照/AI 依据）        → 只在中栏
题级决策（编辑/判定）                  → 只在右栏
```

同层不重复出现另一层的动作。据此消解 P1-1：上下文条「还差 N 题·去确认」改为**只读进度
（N/M + 迷你进度条）+ 点击即等同左栏「待处理」页签并跳到第一个未确认题**——不再是独立按钮，
而是与左栏同源的单一语义。

### 2.2 主按钮矩阵（唯一 primary 随场景切换）

| 场景 | 唯一 primary | 降级为次要 |
|---|---|---|
| 批改进行中（存在未确认题） | 右栏判定区（「✓ 正确 / ✗ 错误」按钮组即主操作区，视觉权重最高） | 顶栏「完成复核」→ secondary（带 n/m）；「▶ 下一份」→ tertiary |
| 全部已确认（confirmed===total） | 顶栏「✓ 完成复核」（保持 success 主样式，并可微微强调） | 右栏判定区整体降透明度禁用；「▶ 下一份」→ secondary |
| 阻断态 / 空态 | 该态自身的引导按钮（维持现状） | 其余全部 tertiary |

实现上只是调整按钮的 `type`/`plain`/`disabled` 组合，不新增组件、不改 token。

### 2.3 面板职责（重构后）

- **左栏 = 队列**。三态页签保留（待处理/已确认/全部，默认全部）；判定后当前题高亮 +
  `scrollIntoView`；「去编辑」等异常题在队列行上保留风险签。置信阈值 slider 移入页签行右侧
  的「筛选」popover（点击才见，P1-5）。
- **中栏 = 证据**。保持缩放/翻页/缩略图不变。新增一条契约：右栏切换题目时，中栏自动定位到
  当前题所在页（若已有该能力则保持），除此之外不做任何自动缩放。
- **右栏 = 决策**。底部判定条**粘底固定**（滚动 Review Card 时不动），构成
  `┌ ✓ 正确(Space) │ ✗ 错误(X) │ ✕ 删除 ┘ + ← → 翻题` 的单行决策区；「编辑」上移到卡片
  头部（与 AI 重解析同排），不再与判定按钮抢底部空间。

## 3. 「看→判→过」工作流重构（核心）

### 3.1 判定即过（解 P0-1）

`handleReview` 成功落库后（含完整性门禁放行、删除确认通过）**自动前进到下一未确认题**：

```
advanceTarget = 当前视图顺序中，当前题之后第一个 未确认(pending/exception/processing) 的题；
若无 → 从头找第一个未确认题（环绕一圈）；
若全卷已确认 → 停留当前题，并触发「完成引导」（见 3.4）。
```

- 前进复用 `store.nextQuestion()` 同一索引机制，仅选择目标不同（需要在 store 增加
  `advanceToNextUnconfirmed()`，纯前端索引逻辑，不触任何 API）。
- **不前进的例外**：标错被完整性门禁拦截时、删除被取消时——动作未生效就不前进。
- ← 仍是纯导航，不变。老师想回头看刚判的题，按 ← 即可，改判走同一判定键（再按一次 X/Space
  覆盖 `review_status`，现有 `reviewQuestion` 本就支持重判）。

### 3.2 归因改为「会话级免打扰 + 收尾批量补」（解 P0-3）

分两阶段：

- **第一阶段（纯前端，本 PRD Batch 1）**：归因弹窗增加「本次批改不再询问」勾选项。勾选后
  本次会话内 `wrong→correct` 一律静默落库（`misjudgeType` 留空，后端统计归为 `unset`，
  与现状「跳过」语义完全一致，无数据结构变化）。
- **第二阶段（需后端，Batch 3，须负责人确认）**：「完成复核」前若本卷存在 `misjudgeType=unset`
  的人工翻案题，弹一次**批量归因清单**（逐题下拉 + 全部跳过），一次性补齐。归因属于
  `judgements` 审计语义的扩展，按仓库纪律不先斩后奏。

### 3.3 撤销诚实化（解 P0-4）

- **Batch 1（纯前端）**：菜单项文案改为「回退上次判定（仅本页显示）」，并在执行后 toast 明示
  「已回退显示；该题在数据库中的记录未变，重新判定会覆盖」。同时把撤销栈在换卷时清空的
  行为显式化（换卷即清空，不跨卷残留）。
- **Batch 3（需后端）**：若业务确认需要真撤销，走 `PUT /questions/:id` 把 `review_status`
  写回 `pending` + 后端回滚错题本同步（`reviewQuestion` 的后端已有 correct 移除/wrong 强入
  逻辑，需幂等逆操作）。涉及错题生命周期，列为待确认项，不在本轮实施。

### 3.4 完成引导（衔接「过」的尽头）

最后一题判定即过、全卷已确认时：右栏判定区切换为完成态——

```
「本卷 N 题已全部确认 → [Enter 完成复核]   [T 下一份]」
```

复用现有 `prepareWrongGate` 错题门禁流程（弹窗逻辑不动），只是把入口前移到了判定区的终点，
老师不用再抬头找顶栏。

## 4. 快捷键设计（解 P1-2 / P2-1）

在现有 4 键基础上扩展，全部沿用 `onPanelKeydown` 的守卫顺序（编辑态禁用 → 输入焦点让位 →
overlay 让位 → 修饰键让位），`hasOpenOverlay` 守卫继续兜底弹窗穿透：

| 键 | 动作 | 说明 |
|---|---|---|
| `Space` | 标对 + 自动过 | 保持现有语义，新增自动前进 |
| `X` | 标错 + 自动过 | 保持现有语义 |
| `Shift+X` | 删除本题 | 复用现有二次确认框（保留，删除不可挽回） |
| `E` | 进入编辑 | 编辑态内 `S`=保存、`Esc`=取消 |
| `←` / `→` | 上一题 / 下一题 | 纯导航，**不**自动判定 |
| `T` | 下一份 | 复用 `goNextTask`；`Shift+T` 上一份（P2-2，需 store 增加 prevTask，沿 pendingTasks 反向） |
| `Enter` | 完成复核 | 仅在全卷已确认时可触发；否则无操作 |
| `?` | 快捷键速查浮层 | 列出全部键位；顶栏「⋯ 更多」加同一入口（P2-1） |

鼠标行为与键盘完全同源：所有新快捷键只调用现有 handler（`handleEnterEdit`/`handleSave`/
`handleReview('exclude')`/`goNextTask`/`handleComplete`），不另写业务分支。判定按钮点击后
`blur()` 消解 P2-4 的 Enter 重复判定隐患。

## 5. 状态机

### 5.1 题目判定状态机（不变 + 新增转换标注）

```
pending/exception/processing ──标对(Space)──▶ correct ──标错(X)──▶ wrong
        │                                        ▲                    │
        └────────────标错(X)─────────────────────┘                    │
             wrong ──标对(Space)──▶ correct   [wrong→correct: 归因收集，见3.2]
        任意态 ──删除(Shift+X, 确认)──▶ exclude（列表移除，不可见）
        wrong 前置门禁：checkQuestionCompleteness 不通过 → 阻断 + 引导编辑（不变）
```

**新增**：任何成功落库的判定（correct / wrong / exclude）触发 `advanceToNextUnconfirmed()`。

### 5.2 任务（卷）状态机

```
reviewing ──confirmed===total──▶ all_confirmed ──完成复核──▶ [错题门禁] ──▶ completed ──▶ 下一份
    ▲                              │
    └──────任意重判(仍≥1未确认)─────┘
```

- `all_confirmed` 是**派生态**（由 `questionConfirmationMap` 实时计算），不是新落库状态，
  不引入新后端字段。
- `all_confirmed` 驱动三件事：顶栏主按钮切换（2.2）、右栏完成引导（3.4）、
  「完成复核」disabled→enabled 时按钮文案从「完成复核 (n/m)」变为「完成复核 · 就绪」。

### 兼容与回滚

- 全部 Batch 1/2 改动不触 API、不触 Schema、不触 `reviewDecision.js` 状态口径（React 移动端
  `ExamReview` 共用该文件，保持零改动即可两端一致）。
- 判定即过提供会话级开关（store 内布尔，默认开），出问题可即时关闭退回手动模式，无需回滚代码。

### 遗留风险

- Space 自动过 + 快速连按可能跳过老师想细看的题——靠 ←/→ 随时可回 + 重判覆盖兜底，不做防抖限制。
- 「下一未确认」的环绕语义在「待处理」过滤视图下的目标选择需在实现时以「纸面题号顺序」为唯一
  序（沿用左栏 visibleItems 的 idx 口径），避免过滤视图切换后跳题顺序漂移。
