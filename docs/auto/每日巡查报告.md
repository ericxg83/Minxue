### 一、发现的 Bug（已自修复）

**B1. 构建环境 Bug：esbuild 临时文件 Access is denied（阻塞一切构建校验）**

- **症状**：`vite build` 在 `[vite:esbuild-transpile]` 阶段失败：`remove C:\Users\...\Temp\esbuild-xxx: Access is denied`。导致巡检 `build=FAIL` 持续多轮（R217 旧 daemon 报告也是 FAIL）。
- **根因**（实测确认）：本机是 WorkBuddy LiteSandbox（`LSBOX_AUDIT_SHMEM`），拦截系统 `%TEMP%` 下 esbuild 原生二进制临时文件的「创建→删除」（与本机已知的「同步子进程带管道 stdin 必 EBUSY」同源）。进程退出后文件可正常删，说明是运行期句柄被沙箱审计层挡。
- **修复**：把 esbuild 临时目录指到工作区内 `logs/esbuild_tmp/`（已被 `.gitignore` 覆盖）：
  - `scripts/nightlyAudit.mjs` `collectBuild()`：构建 env 注入 `TMP/TEMP/TMPDIR = logs/esbuild_tmp`
  - `scripts/patrol/patrol.mjs` 构建调用：同样注入
- **验证**：nightlyAudit 全跑 → **lint 0 error / tests 2315-0 / 构建通过（7.3 MB）**；patrol 引擎 → build ok。修复前后 A/B 复现成立。
- **影响范围**：仅巡检/构建脚本，不改业务代码。**回归测试提名**：`test/esbuildTmpEnv.test.mjs`（断言 collectBuild 的 env 含工作区内 TMP 指向；属加闸，需负责人同意后再建）。

**B2. 仓库卫生：186 个历史构建目录堆积（1.33 GB）**
