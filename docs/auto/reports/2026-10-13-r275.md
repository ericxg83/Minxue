## 一、病根（r249 实测，2026-10-09 发现）

`/api/tasks/summary` 的 `failedTasks` 只数**未读**失败（SQL 里 `AND notification_read_at IS NULL`）：

- 老师点一次铃铛（标记已读），那条**永远批不成**的作业就从「失败任务」灯、待办总数里**永久消失**——不是修好了，是看不见了；
- 同一个数字同时挂两件事：铃铛角标要「未读」，失败灯要「总数」，口径天生打架；
- 「没看的新作业」（未读 done）本就归「待确认」卡（pendingReview），失败灯再兜一份未读失败，两卡语义互相渗透。

## 二、方案（负责人批准的拆分：一个数字不再挂两件事）

### 后端 `server/index.js`（+22 行）

1. `failed_detail` 子查询**去掉 `notification_read_at IS NULL` 过滤** → 取全集（含已读）；
2. SELECT 补 `t.notification_read_at`（JS 侧派生必需）；
3. JS 侧：`failedReal`（排除还会自愈的）→ `failedTasks = failedReal.length`（真失败总数，失败灯用）、`failedUnread = failedReal 中未读的`（铃铛用，与 pendingReview 同「未读」口径）；
4. `totalNotifications = pending_review + failedUnread`（未读 done + 未读失败）——**不许**用 failedTasks 相加，否则已读失败会圈进「待办」，老师点开后角标永不归零。

### 前端三处（+11 行）

- `notificationStore.js`：summary 初始值加 `failedUnread: 0`；
- `NotificationList.vue`：「失败任务」卡数字 = `summary.failedTasks`（真失败总数），卡内注释写明口径与历史病根；
- `DashboardWorkbench.vue`：`failedCount` 继续读 `failedTasks`（口径自动变准），注释记录旧口径塌缩问题。

### 测试锁 `test/taskAutoRetry.test.mjs`（+29 行）

- 旧断言改写为新派生链（failedReal → failedTasks/failedUnread → totalNotifications 用 failedUnread）；
- 新增专锁「failed_detail 必须取全集」：**断言前先剥 SQL 注释行**——r275 注释里刻意写了「去掉 notification_read_at IS NULL」这句话，不剥注释判据会被自己的注释判红（nightlyAuditTestScope 同款坑）；
- SELECT 断言锚 `updated_at,\s*t\.notification_read_at` 而非宽松的 `/t\.notification_read_at/`——旧版 WHERE 里也有这个串，放宽则旧版判不出红（反向自检：真旧版两处判红验证通过）。
