### 1.2 关键事实（这三条决定了方案形态，务必先读）

1. **`error_type='未作答'` 是故意的，不是 bug。**
   `server/services/neonService.js:486`（另有 `:600`、`worksheetPageService.js:62/75`、
   `scripts/backfill-blank-wrong-questions.mjs`）在写空题时同时写 `is_blank=true` + `error_type='未作答'`，
   注释明写「移动端列表直接显示『未作答』」。498/498 条实测 `is_blank=true` 且 `error_reason IS NULL`，
   9 月 210 / 10 月 241 / 11 月 47，**仍在持续新增**。
   ⇒ **禁止改这个写入逻辑**（移动端列表依赖它），问题只在「统计层把它当成了错因」。
2. **`runErrorDiagnosis` 只处理 `error_type IS NULL` 的行**（`diagnosisService.js:232`）。
   ⇒ 改 prompt 天然只影响新错题，**存量 2074 条不会被重跑**（符合「掌握度/诊断增量累加，禁止重跑重算」铁律）。
3. **`error_reason` 是 `text` 无长度上限**（information_schema 实测）。
   ⇒ T0 阶段可以把结构化内容直接塞进去，**不需要加字段**。`ai_confidence` 是 `numeric`，`is_blank` 是 `boolean default false`。

## 2. T0 — 零 Schema 变更（可立即开工，A 级自决）

### T0-1 错因 prompt 改「三段式」（核心）

**目标**：不再让模型直接选错因标签，强制它先定位出错环节。

**改动点**：`server/services/diagnosisService.js:118` 的 `buildErrorAnalysisPrompt()`

要求模型返回的 JSON 增加三个字段（**`error_type` 仍必须来自 `error_types` 词表，绝不放宽**）：

```json
{
  "error_step": "学生在哪一步开始偏离（引用学生的具体写法，如『移项时把 -3 写成 +3』）",
  "error_type": "计算错误",
  "misconception": "具体错误认知，一句话（如『认为移项不变号』）；无明确认知偏差时给空串",
  "missing_prereq": "需要回补的前置知识，一句话；无则给空串",
  "reason": "一句话错因",
  "confidence": 0.9
}
```

- 若 `error_step` 无法从「学生答案」中看出（只有最终答案、无过程），**必须给空串并在 reason 里注明 `证据不足`**，
  不许编造步骤 —— 这条是本任务的质量核心，写进 prompt 的硬性要求。
- 落库：**只写一句具体判语到 `error_reason`**（现有代码已有 80 字硬截断）。
  ⛔ **2026-11-22 执行时更正（原方案作废）**：原设计要把 `【步骤】…｜【迷思】…` 结构化前缀写进 `error_reason`，
  实测**不可行**，两个理由：
  ① `error_reason` 的消费方 `server/services/englishAnalyzer.js:189` `classifyEnglishErrorType()`
     会把它拼成正则 haystack，而 `/the\b/`、`/复数/`、`/to\s+do|doing|done/` 这类模式极宽
     ⇒ 塞前缀会污染英语题的错因归类；
  ② 它是**展示字段**（`WrongBookCenterRedesign.vue` 的 `.error-reason` 块 + pill 的 `:title`），
     把存储职责塞进展示字段违反「一个字段一个语义」。
  ⇒ `error_step` / `misconception` / `missing_prereq` 仍由模型输出，但**只进 `runErrorDiagnosis` 日志供抽检，
  不落库**；等 T1 加列后才正式入库。
- `analyzeErrorLocally()`（本地启发式）**不动**：它只处理「数字对得上但漏单位」这类高把握场景，不需三段式。

**验收**：
- 新生成的错题 `error_reason` 含 `【步骤】` 标记的比例 ≥ 80%（解答题）；
- 选择题/填空题允许证据不足，但 `reason` 必须出现「证据不足」而非编造；
- `error_type` 100% 落在 10 类词表内（跑 50 条抽样断言）。

## 4. T2 — 租卡横评（不常驻，一次性）

**问的问题**：OmniEdu-27B 在**我们自己的**错题上，诊断具体性是否真的强于现有 prompt + 通用模型。

- 样本：本地 200 道非空错题（覆盖数学/英语，优先"概念不理解"395 条里抽）
- 对照：A = 现有链路（`diagnosisService` + 现 prompt）；B = OmniEdu-27B（vLLM 起 OpenAI 兼容服务）
- 判据：① 具体性胜率（盲评，老师视角"哪个更能告诉我下一步讲什么"）；② `error_type` 一致的样本占比；③ 单题耗时/成本
- **结论只允许是**：「值得进 T1 链路」或「不值得」，不许因此立项常驻部署

**禁止**：不接生产链路、不做常驻服务、不拿它当"零错字"真值（PDF 文本层才是真值）。
