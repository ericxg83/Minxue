```bash

  npx vite build --outDir dist_nightly_YYYYMMDDrNN
npx vite preview --port 52xx --outDir dist_nightly_YYYYMMDDrNN   # 必须带 --outDir！
```

1. ⛔ `vite preview` 不带 `--outDir` 服务的是**陈旧 `dist/`**（r94 把旧产物里的已删页面当成回归，
   白查一轮）；冒烟前必须 `curl` 一个只在新产物里存在的 asset 验证服务对象

2. ⛔ `MSYS_NO_PATHCONV=1`：Git Bash 把 `/api` 改写成 `C:/Program Files/Git/api`（r95 实测 22/33 假红）。
3. ⛔ `VITE_API_URL=/api`：否则 `.env.production` 的生产 base 被烤进 bundle，产物一半直连生产。
4. ⛔ `CODEBUDDY_SAFE_DELETE_ENABLED=0`：否则清空已有 `--outDir` 被安全删除守卫拦。
5. 「0 控制台错误」抓不到「点了白屏」（只打 router **warning**）/「点了没反应」（只打 Vue **warning**）
   ⇒ 必须配源码级入口锁。
6. Windows 上 `TaskStop` 杀不干净 preview 子进程 → `netstat -ano | grep :PORT` + `taskkill //F //PID`。

## 七、问题：技能把「每轮临时件」当成常驻工具

（均 `.mjs`；`_verify_xxx` / `xxx.test` 是 `minxue-product-review` 里的占位符，非真实引用。）

**根因**：项目约定 `_*` 脚本是**每轮临时件、不入库**（`docs/auto/HANDOFF.md` 第六节明写

下一个会话会去找文件、找不到、然后怀疑环境坏了。**上一轮我还给其中一个补了 `cd server`，
把「路径对但文件没有」修成了更迷惑的状态。**

## 八、修法

1. **逐处加内联标注**：脚本名与「已不在仓库」**写在同一行**（便于 grep，也让读者一眼看到），
   并在旁边给出**重写规格**（该脚本原本做什么、怎么写）。
2. **改掉误导性标题**：`minxue-workbench-ui-verify` 的
   「## 现成回归脚本（可直接复用/扩展）」→「## 回归脚本规格（脚本本身是临时件，已不在仓库；照描述重写）」；
   正文里「已就绪的复现脚本」→「复现脚本规格」。
3. **`minxue-product-review` 澄清**：`server/_diag_anchor_dup.mjs` 是**要你新建的探针名**（不是已有文件），
   代码块给的是完整实现，照存即可。

## 九、验证

- 13 个缺失脚本 + 4 个自带脚本，逐个确认「文件名所在行（或其上一行）含『已不在仓库』」——

- 复查方式：把「技能里出现的所有 `.mjs`」与「仓库全部 `.mjs` 文件名清单」做集合差，

## 十六、实跑暴露的 2 个真实缺陷（已修）

| # | 缺陷 | 旧行为 | 后果 |
|---|---|---|---|
| 1 | **无参数时静默退出 0** | 输出空、退出码 `0` | 读 `ocr_result.txt` 的人会误判成「**图里没有字**」，进而答错或编内容 |
| 2 | **坏路径直接抛 traceback 并中断整批** | `LoadImageError` 栈回溯，脚本退出 | **后面的图一张都不识别**；多图批处理时前面的错路径会静默吃掉其余全部工作 |

**修法**（`scripts/ocr_clipboard.py`，纯增量错误处理，成功路径行为不变）：

- 无参数 → stderr 打用法、**退出码 2**；
- 逐张 `try/except`，失败项在 stdout（即 `ocr_result.txt`）打一行 `ERROR: …`，
  **其余图继续识别**；有失败则**退出码 3**；
- 成功仍为 `0`，单图无文字仍输出 `NO_TEXT`。

**实测三种情形**：无参数 → `exit=2` + 用法；坏路径+好图 → `exit=3`，好图**照常识别**；
仅好图 → `exit=0`，输出与旧版逐字一致。

技能文档同步补了「**看退出码再下结论**」对照表（并写明「别把空结果当成图里没字」）。

> 另：`verify-skill-existence` 技能无自带脚本、无外部依赖，无可实跑项。
