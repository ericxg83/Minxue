## 三、结论：非缺陷，止损（不擅改）

重叠仅限「原生前台」的 30s 双 tick，且三重吸收，无行为危害：

1. **DB/网络成本被服务端缓存吸收**：`/api/tasks/summary` 自带 10s TTL 缓存（`server/index.js:717` `SUMMARY_TTL=10000`、`:726` 命中即返）→ 同窗口第二次调用命中缓存，DB 查询至多每 10s 一次。
2. **状态无分歧**：A、B 都把**同一份** `data.summary` 写进 `setNotifSummary`（`App.jsx:327` / `notificationService.js:151`）⇒ 不会写出错数据、不会串值。
3. **系统通知不去重也会重复弹**：`dispatchFromSummary`（`notificationService.js:86-140`）用 localStorage 持久化的 `notified` Set 去重（`loadNotifiedIds`/:89、`notified.add(t.id)`/:109、`saveNotifiedIds`/:114），同 id 同周期只弹一次 ⇒ 两条轮询不会触发重复 OS 推送。

**两者是互补而非冲突**：B 必须在后台跑（系统推送依赖），但 B 没有 `visibilitychange` 监听（不会切前台立即刷新）；若删 A，角标会滞后最多 30s 才在切回前台时更新。若删 B，则后台不再弹系统通知。收益/风险不成正比 ⇒ **判非缺陷，不擅改**。
