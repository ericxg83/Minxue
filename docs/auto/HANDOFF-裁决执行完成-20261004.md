## 三、⑧ 的解释：为什么 `VITE_AI_API_KEY` 客户端直读是 foot-gun

**现状**：`src/config/ai.js` 第 8 行在前端代码里直接读环境变量 `VITE_AI_API_KEY`。
Vite 构建时会把这个值**原样写死进发出去的 JS 文件里**（`import.meta.env.VITE_*` 全部在
构建期做字符串替换）。

**类比**：把 API key 写在前端代码里 = 把钥匙焊在门口的锁上——任何拿到网页 JS 的人
（浏览器开发者工具里就能看到）都能取出来用。后端代码里的 key 才是「钥匙在自己口袋里」。

**风险等级**：目前**没有泄露**——本仓库 `.env.production` 里是占位符 `your-ai-api-key`
（r95 已取证）。但如果将来有人把真 key 填进这个变量，key 就随前端包公开发布。

**要负责人拍板的问题**：前端直连 AI（浏览器 → 魔搭 API）这条路现在还在用吗？
- 若不用 → 把 `config/ai.js` 和相关死代码删掉即可（A 级）；
- 若还在用 → 建议把 AI 调用挪到后端代理（前端 → 自己的 /api → 魔搭），key 只存服务端
  （涉及架构调整，C 级，需专门一轮）。
